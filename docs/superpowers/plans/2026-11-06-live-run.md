# Live Run Feedback Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (no subagents, by user request; the final review is a self-review). Steps use checkbox (`- [ ]`) syntax.

**Goal:** While ▶ Run runs a program with the Graph in view, the Graph shows where it's at: the running function (or its module) glows, sparks travel along calls, API boxes glow when their function runs.

**Architecture:** A bundled standard-library Python tracer (`src/main/runTrace.py`) starts the user's program through `runpy` with a profile hook for project files only, and sends ~10 updates a second over a local socket. The main process opens the socket per traced run and forwards updates to the window. A pure planner (`src/renderer/graph/liveRun.ts`) turns an update into "glow this node, spark these edges, light these boxes" for the current view; GraphView draws it.

**Tech Stack:** Python 3 standard library (`sys.setprofile`, `threading`, `socket`, `runpy`, `json`), Electron main (`node:net`), TypeScript, vitest.

**Spec:** `docs/superpowers/specs/2026-11-06-live-run-design.md`

## Global Constraints

- Traced only when the Graph is visible when Run starts and Settings → "Show runs on the graph" (`showRunsOnGraph`, default true) is on. Debug and Tests are never traced.
- Program behaviour unchanged: same stdout/stderr, stdin, exit code, `sys.argv`, `sys.path[0]`, `__main__`; tracer frames never appear in tracebacks; tracer failure = untraced run.
- Only files under the project root, excluding `.venv`, `venv`, `env`, `site-packages`, `node_modules`, `.forge`, are traced.
- Updates ≈ every 100 ms: `{"t":"tick","at":<id|null>,"calls":[[from,to,count],...]}`; first line `{"t":"hello","token":...}`; last `{"t":"end"}`. Ids: `module:qual` for functions, `module:<module id>` for module-level code (the Graph's ids).
- Visuals: glow fades ~0.6 s; ≤ 12 sparks per update, busiest first, ~0.5 s each; Plain = dot + highlight, no glow; reduced motion = highlight only. Theme tokens only.
- No in-app runs (user rule). Commits as before (`louisatron84`, Co-Authored-By trailer).

## Review Focus

1. A script that raises: the traceback must start at the user's file (no `<string>`/`runpy` frames) and the exit code must be 1.
2. `sys.exit(n)`, `input()`, and `if __name__ == "__main__":` behave exactly as untraced.
3. `-m package.module` runs (run configurations), with `sys.path[0]` = cwd like `python -m`.
4. The socket can't connect (port closed): the program runs normally.
5. A run that ends while sparks are in flight leaves no stuck glow.
